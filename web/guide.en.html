CELL SCOPE LAB · ORIGINAL RESEARCH PLATFORM

From raw battery data to defensible experiments

The HTML site teaches and visualizes; Python CLI performs actual training. No benchmark accuracy is invented, and the included example data are synthetic.

01 / Quick start

python -m pip install -e '.[all,test]'
python -m cellscope demo --out examples/generated/synthetic.csv
python -m cellscope models
python -m cellscope train --config configs/soc_demo.json --out runs/soc_demo
python -m cellscope compare --config configs/soc_demo.json --models mean,ridge,mlp,gru --out runs/compare

02 / Task labels and source fields

Required canonical CSV fields: cell_id, cycle_index, time_s, voltage_v, current_a, temperature_c and task-specific soc, soh or rul_cycles. Labels must be source-defined, not inferred from the file endpoint. SOC is a 0–1 fraction by design; RUL requires an actual, observed end-of-life (EOL) criterion.

03 / Data quality and preprocessing

Check sorted time, duplicate timestamps, time gaps, current sign and charge/discharge phases, sensor units, capacity resets, non-finite values, cycle boundaries and SOC label alignment. Do not interpolate long gaps or fabricate contiguous windows from disconnected segments. Fit MinMax/Z-score, imputation and feature selection inside the training fold only.

04 / How to split a time series

Unseen batteries require a battery-group holdout or leave-one-cell-out validation; a known cell's future requires chronological holdout and a suitable boundary purge; leave-one-cycle-out measures new cycles of known cells, not unseen-cell generalization. A temperature/profile split additionally requires a cell-identity audit. The current CLI supports battery and cycle splits, while the new adviser is explicitly educational guidance.

05 / Model library and code

All 22 registered models are visible in the interactive architecture theatre. A separate code reader extracts real model construction, forward and training excerpts from cellscope/models.py, with source digest and full repository links. Paper-inspired PatchTST-lite and iTransformer-lite are simplified alternatives, not verified paper reproductions.

06 / Neural network fundamentals

25 components cover activations, normalization, optimizers, weight decay, dropout, convolution, GRU/LSTM, attention, residuals, learning schedules and interpretability. Plot ReLU, GELU, sigmoid and tanh; understand training versus inference. Examples are educational, not observed learned model activations.

07 / Metrics: regression versus classification

For SOC / SOH / RUL regression use MAE, RMSE, R², bias, low-SOC subgroup metrics and appropriately documented scaling. For battery-fault classification, accuracy, precision, recall, F1, MCC, confusion matrices and ROC-AUC can be appropriate. AUC requires continuous scores for both positive and negative examples. The classification calculator is a teaching tool; the Python backend does not currently train a classification task.

08 / ADV·BATTERY knowledge atlas

The browser requests the public ADV·BATTERY JSON catalogs on demand and links back to original providers and related papers. If the network blocks GitHub Raw, curated offline source cards appear with an explicit notice. Original experimental datasets are not mirrored and their licenses are not implied.

09 / Volt learning guide and privacy

The battery-shaped mascot on the right opens a dedicated document-flow help panel, not a floating overlay. It is a deterministic template-based educational guide, not a generative AI service, and it does not transmit questions to an external chat API. Hide it at any time.

10 / Testing and scientific boundary

Python unit tests, JavaScript numeric/structure tests, source extraction and asset checks are automated. The available Chromium build is administrator-blocked from navigating URLs, so genuine cross-browser click-through verification remains outstanding; see WEB_QA.md. Demonstration predictions are not public-dataset benchmark results.
